# 1. Snapshot System

## 1.1 存储布局

```text
<workspace>/.latex-studio/snapshots/
└── <snapshotId>/
    ├── manifest.json
    └── files/
        └── <workspace-relative paths…>
```

- 位于 `.latex-studio/` 内：File Watcher 的 IGNORED 规则已覆盖，
  快照读写永远不会触发 re-index（防循环由既有过滤保证）。
- v1 采用全量拷贝（源文件集合 = 索引器同一套排除规则，
  谓词从 `fileWatcher.ts` 导出复用）；增量格式明确延后，
  待真实体积数据出现再评估（记录于 V0.7 候选）。

## 1.2 Manifest Schema（硬约束）

```json
{
  "snapshotId": "snap_20260826153000_a1b2c3",
  "workspaceId": "<sha256(root)[0..16]>",
  "createdAt": 1767000000000,
  "reason": "manual | auto | build-ok | pre-replace | pre-restore",
  "label": "可选人工标注",
  "mainFile": "main.tex",
  "fileCount": 42,
  "totalBytes": 1048576,
  "contentHash": "<sha256(sorted(relPath + ':' + fileHash))>",
  "files": [
    { "path": "chapters/ch1.tex", "hash": "<sha256(content)>", "size": 2048 }
  ]
}
```

- `contentHash` 相同 → 跳过创建（内容无变化）
- `files[].hash` 支撑 diff 与 restore 时的最小写入集计算

## 1.3 触发点（全部落地为服务端 API，前端只调用）

| reason | 触发方式 |
| --- | --- |
| `manual` | `Ctrl+Shift+S` / 工具栏时钟按钮 / Palette |
| `build-ok` | 编译成功后自动打 "known-good" 快照 |
| `auto` | 可选：焦点丢失且存在脏文件时（默认关闭） |
| `pre-replace` | Project Replace All 应用前强制创建 |
| `pre-restore` | 恢复任何历史快照前强制创建 |

保留策略（设置可调）：24h 内全保留 → 30 天内每日合并一份 → 总量上限 30 份
（最旧先淘汰）。聚合 `contentHash` 与最新快照一致时静默跳过。

## 1.4 Restore 流程（硬规则）

```text
选择快照 → Preview Diff（Monaco DiffEditor：
  base = 所选快照, compare = 当前工作区）→ Confirm → Restore
```

- Restore 执行前自动创建 `reason: "pre-restore"` 安全快照
- **禁止任何形式的无提示一键覆盖当前工程**
- 支持整快照恢复与单文件恢复
- 恢复产生的大量写入被 watcher debounce 合并为一次增量 re-index
  （快照目录本身在忽略清单内，不会形成循环）

## 1.5 生命周期与集成

- 与编辑器保存、workspace 打开/切换同层设计：
  open workspace → ensure snapshots dir → watcher start（互不复用句柄）
- BuildManager 编译成功后调用 `create({ reason: 'build-ok' })`
  （best-effort，失败不影响构建结果）
- Search & Replace All 在应用前调用 `create({ reason: 'pre-replace' })`

# 2. Project Search & Replace

## 2.1 搜索

- 入口：`Ctrl+Shift+F` 侧边面板（Search 标签）
- 能力：大小写敏感 · 全字匹配 · 正则（带求值超时保护）·
  文件 glob（如 `chapters/**`）· 默认排除 `.latex-studio/.build/产物扩展名`
- 服务端：`POST /api/search` — 复用索引器的 walk 与 stripComments 规则，
  返回 `{ matches: [{ file, line, column, preview }] }`，
  结果按文件分组、支持点击跳转（复用 `openFileAtLine`）

## 2.2 替换

- `POST /api/search/replace`：
  `{ query, replacement, scope, preview: true }` → 返回逐文件变更预览
  （每处修改的前后行上下文），确认后携带 `confirmToken` 二次请求应用
- **Replace All 应用前强制创建 `pre-replace` 快照** —— 与快照系统闭环：

```text
Search/Replace → Automatic Snapshot → Preview Diff → Apply
```

## 2.3 性能预算

1000 文件项目内搜索 < 1.5 s；替换预览 < 2 s；应用 < 1 s
（复用 mtime 缓存避免重复读取）。

# 3. Paper Statistics

## 3.1 统计模型（自建，非 texcount 包装）

对剥离注释后的正文逐字符分类计数：

| 类别 | 规则 |
| --- | --- |
| Chinese characters | `[\u4e00-\u9fff\u3400-\u4dbf]` 逐字计入 |
| Latin words | 连续 `[A-Za-z]` 序列计为一个词 |
| Numbers | 数字序列单独计数 |
| Total visible text | 以上三类之和 |

**排除项**（不计入）：LaTeX 命令与其花括号内的非正文参数
（label/cite/ref/includegraphics 目标等）、注释、导言区、
宏定义体、文件路径。数学环境体不计词数，仅记公式个数
（公式个数来自 Project Graph）。

## 3.2 三级聚合

```text
Project   → 全项目合计
Chapter   → 按 \chapter 边界切分（无 chapter 时退化为顶级 \section）
Section   → Outline 树每个节点的子树合计
```

实现基于 Project Graph：section 节点已含 file+line，
按行号区间将各文件贡献归属到对应章节节点——零额外扫描。

## 3.3 展示

- `GET /api/statistics` 返回上述三级结构
- 入口：Navigator 头部 "Stats" 按钮 → 全屏统计视图：
  项目总表 + 章节条形分布图（纯 CSS 条形，无图表库）
- 典型场景：中文学位论文字数要求核对（按汉字字符数）、
  章节平衡检查

# 4. Supporting 功能

## Auto-save policy

`off | 30s | focus-loss`（默认 off）。触发时对所有脏标签执行
saveFile（走既有保存管线：dropBuffer → saved 事件 → buffer 重索引 →
Auto Compile 链路）。与快照联动：auto-save 不触发快照，
build-ok 才触发。

## ZIP Export / Import

- 导出：`GET /api/project/export` — 源文件集合打包
  （排除规则同快照），文件名 `<name>-<date>.zip`
- 导入：`POST /api/project/import` — zip 缓冲 + 目标目录；
  每个条目路径过 jail（拒绝 `..`/绝对/盘符/UNC）· 大小上限 200 MB ·
  非空目录拒绝合并除非显式 `merge: true`
- 依赖：`jszip`（纯 JS ~100 KB）—— 本功能必需的新依赖，
  Node 无原生 zip 支持，PowerShell 方案破坏跨平台
